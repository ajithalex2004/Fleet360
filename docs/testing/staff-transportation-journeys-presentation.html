JOURNEY 01

Staff / Passenger

ACTOR: REGULAR EMPLOYEE

The staff member's day from wake-up to alighting. They mostly interact through the staff portal at /bus-ops/passenger/* — no admin access, no driver app. The journey's power move is the absence request → seat-freed → waitlist-promoted chain.

NO-OP FOR STAFF
BLE boarding is passive

Staff member walks up. Their tag's RSSI crosses -75 dBm with 3+ samples in window. They never tap, scan, or press anything. Trip just gets recorded.

THE ABSENCE CHAIN
Sweep unlocks the seat

Without Phase 1, the sick staff member's seat stays reserved and the bus leaves with a free seat someone on the waitlist could've taken. Two-phase sweep fixes this.

SAME ENDPOINT, 3 PATHS
BoardingEvent.source field

BLE, QR, and geofence all write to the same table. The source field is the only difference. The state machine doesn't care which path you came from.

MONEY MOMENT
Trip-end fires the outbox

The dispatch board shows COMPLETED, but the GL entry is async. If the consumer fails, the outbox row stays unpublished and is retried up to 10 times. Money doesn't get lost — it gets delayed.

IDEMPOTENT BY DESIGN
Replay-safe consumers

Both bridge functions are idempotent on expense_no = 'FUEL-{id}' and (BUS_OPERATIONS, BUS_TRIP, scheduleId). A redelivered event returns the same row, not a duplicate.

CONTINUOUS
Heartbeat every ~30s

Driver app posts GPS + alive signal while a trip is active. The dispatch board's live map is just the latest heartbeat per vehicle.

R10 FIX
Dry-run before commit

Operator pastes a 200-row CSV. ?dryRun=true returns counts with zero writes. They fix the 3 bad rows. Then ?idempotencyKey=op-paste-... commits. Same key twice = replay, not duplicate.

DEPART GHOST PASSENGERS
NO_SHOW is the silent passenger

When status moves to DEPARTED, every CONFIRMED passenger who didn't board gets flipped to NO_SHOW. Not ABSENT (per-stop miss) — NO_SHOW is the whole-trip-no-show.

TRIP COMPLETION
The money flows after

Trip status → COMPLETED is instant on the dispatch board. The GL entry to 5145 Bus Op Expense is async via the outbox. Dispatcher never waits for finance to be ready.

JOURNEY 04

Cross-Tenant Isolation

ACTOR: MULTI-TENANT SYSTEM

Two companies share one database. Tenant A's admin must never see, mutate, or be billed for Tenant B's data. This is enforced at the Postgres RLS layer — not at the Prisma client — so it's a hard physical barrier, not a "please don't" comment.

PHYSICAL BARRIER
Postgres RLS, not Prisma filter

withRequestRls in src/lib/prisma.ts sets app.tenant_id via SELECT set_config(..., true). The RLS policy is in Postgres, not the app — a buggy route handler can't accidentally bypass it.

CRON IS DIFFERENT
Platform-wide by design

The auto-close-trips and outbox-publish cron jobs legitimately need to touch every tenant. They use withSystemJob which explicitly opts out of the RLS wrapper. The waitlist sweep can pass ?tenantId= to scope down if needed.

BLAST-RADIUS TEST
What a Tenant A test should prove

Seed two tenants with overlapping employee IDs and route names. As A, query for the conflicting rows. Expect 404s (RLS hides B's rows from the SELECT). PATCH B's row id from A's session — expect 404, not 200.

JOURNEY 05

Idempotent Retry

ACTOR: OPS TEAM (HR PASTE)

An operator pastes a 200-row CSV from HR into the bulk-import route. They hit submit twice by accident (double-click, network timeout, browser refresh). The second paste must be a no-op — not 200 duplicates of the same row. The contract: same key + same body = replay; same key + different body = 409.

THE EXPLICIT MEMO
bulk_import_jobs is the contract

Instead of relying on a DB-level unique constraint (which would 500 on duplicates), the route stores an explicit memo: "For this (tenant, key) pair, I owe this result for 24h." Cleaner UX, structured error, replay support.

THE 409 IS A FEATURE
Reused key + different body = 409

If the operator pastes the wrong CSV under one key, then the right CSV under the same key, the second call gets 409 — not silent overwrite. They have to generate a fresh key, which makes the wrong-data scenario explicit instead of letting it propagate.

24H TTL
Key expires

IDEMPOTENCY_TTL_HOURS = 24. After 24h the key is treated as never seen. Long enough to cover a workday's worth of double-clicks and retries. Short enough to not let stale keys leak forever.

CLOSING

What this means for testing

If a new test doesn't protect one of these five journeys, it's testing the wrong thing. Every test in the repo should be reachable from this index.

COVERAGE GAP

J1-J5 cover ~70% of the surface. The remaining 30% (CBAs, geofence geometry, route optimisation, headway timezone) is *not* yet covered end-to-end.

TEST-FIRST ENTRY POINT

For a new rule, find the journey in this page. Write the test as a step in the flow. The path from the test back to the rule should be a single click in the inventory.

WHAT'S VERIFIED TODAY

Existing tests cover: gateway signature (BR-BLE-01..03), trip-completed consumer (BR-FIN-01/02), WebAuthn (BR-WA-01..06), bulk-import (BR-IMP-01..14), waitlist tenant scoping (BR-SW-07). 8 of 60+ business rules.

WHAT'S NEXT

Highest leverage: trip-lifecycle E2E (BR-TRIP-01..10 + state machine + DB trigger), detectTransitions truth table (BR-BLE-04..08), cross-tenant blast-radius test (J4).
