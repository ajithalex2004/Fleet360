---

## How to read this

Each gap has an ID (stable across both documents), a severity, the stage it sits in (see the mind map / sequence doc), the business impact in plain terms, the root cause, and a recommendation. Severity is about **business consequence**, not code complexity:

- **Critical** — breaks the core revenue workflow today, no workaround
- **High** — a real feature is unusable or invisible to users despite existing
- **Medium** — a real reliability, integrity, or safety gap that hasn't caused visible failure yet
- **Low** — cosmetic or minor consistency issue

- **Contract management (`contracts-v2`)** — full real CRUD: list, create, add-vehicle, generate payment schedule, PDF export.
- **Credit assessments** and **transfers** — genuinely complete end-to-end.
- **Amendments** and **early terminations** — real, including cascading side effects (e.g. an executed termination correctly flips the parent contract to `TERMINATED`).

- **Field Operations app** — a genuinely wired mobile capture surface for mileage, fuel, and traffic-fine entries, feeding the same real API endpoints as the desktop pages.
- **CRM & Leads, Branch Staff Management, Bulk Import** — all fetch/write against real endpoints (`/api/leasing/crm`, `/api/branch-staff`, `/api/leasing/import/[resource]`); their only gap is G5 (no nav entry), not functionality.
- **Dunning sweep logic itself** (classification, message content, activity logging) is genuinely built — G2 (nothing triggers it) and G19 (delivery can no-op) are the actual gaps, not the business logic.
- **V1→V2 contract model migration is complete** at schema and UI level — G15/G18 are leftover cleanup items, not an active duplication risk.

## Recommended sequencing

If planning a remediation pass, tackle in this order — each unblocks the next:

1. ~~**G1**~~ — **done.** Quotations are the funnel entry point; nothing else mattered while this was broken.
2. ~~**G2**~~ — **done.** Fixed scheduling for the platform actually in use (Railway) — this unblocks G9/G19 and half the Medium gaps, which were downstream of "nothing runs automatically." (Surfaced a new one in the process: **G23**.)
3. ~~**G3**~~ — **done.** Approval UI wiring; the backend already existed, this was a frontend fix.
4. ~~**G5**~~ — **done.** Nav exposure; unlocked 12 already-built, already-working pages including the lessee master record. (Turned out the original count was off — see the G5 row for the corrected stub inventory.)
5. ~~**G7, G6**~~ — **done.** Closed both half-built loops (renewal → contract, pricing line items). Also fixed G17 and a G1-class `tenantId` bug in the quotation-conversion path, found while building the G7 fix.
6. ~~**G4, G11**~~ — **done**, after a scoping conversation since both were product decisions, not just bugs. G4 got the plumbing (provider interface + manual reconciliation) rather than a live gateway, since none is configured anywhere in this deployment. G11 got the full self-service portal, including payment/e-sign/upload/damage-report/renewal-request. Live gateway integration remains a genuine future task once a payment provider is chosen — swapping one in means implementing `PaymentProvider`, not rewiring call sites.
7. ~~**G13, G14, G16, G19, G20, G21, G22, G24**~~ — **done.** G14 turned out to already be fixed (stale comments, not a real gap). G13 was the standout: fixing it properly required direct production DB introspection, which surfaced that three tables thought to already be tenant-scoped-unique from an earlier migration actually weren't (a constraint/index name mismatch made the cleanup step a silent no-op), and turned up two more critical, previously-undiscovered bugs along the way — both leasing invoice sweeps (`traffic-fines/sweep-bill`, `fuel/sweep-bill`) had never actually created an invoice due to a Prisma API misuse, and the mileage-overage billing path bypassed RLS entirely. G24's fix also surfaced and fixed an unrelated bug that was blocking every deploy of this branch outright (a client component importing a server-only route module). **G15** investigated but deliberately left as-is — deletion risked breaking an existing RBAC test that asserts against the exact route path; needs a coordinated change with the test, not a solo cleanup. **G12** confirmed intentional, no action. **G18** is a missing historical artifact (a preflight-checklist doc that was never written before a past migration) — nothing to retroactively fix in code.
8. ~~**G23**~~ — **done.** Set `PUSH_CRON_SECRET` in the Railway production environment; verified live (wrong secret → 403, correct secret → a real 164-tenant scheduler run).

Every gap in this document (G1–G24) is now resolved, confirmed-already-fixed, or — for G15 and G18 only — deliberately left as documented, low-risk, non-urgent items (a coordinated test-and-route removal, and a missing historical artifact with nothing left to retroactively code).
